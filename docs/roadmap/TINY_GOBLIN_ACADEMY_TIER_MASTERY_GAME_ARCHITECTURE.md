# Tiny Goblin Academy — Tier Mastery Game Architecture

## Status

- Curriculum doctrine: proposed and recorded
- Implementation: not started
- Tier 1 mastery concept: preserved separately in the external game-development seed shelf
- Final title: unresolved
- Production scope: unresolved
- Schedule: deferred
- Repository: not created

This document records curriculum architecture, not authorization to build a mastery game.

## Purpose

Each substantial Tiny Goblin Academy tier may culminate in a mastery game that recombines the tier's separately taught capabilities into one coherent game.

A normal tier game asks:

> Can this capability be created and validated?

A mastery game asks:

> Can all these capabilities operate together as one understandable game?

The mastery game is not an eleventh ordinary lesson. Integration is the new lesson.

## Mastery-Game Doctrine

1. Lessons teach individual capabilities.
2. Bounded games prove those capabilities in isolation.
3. A tier assembles a capability family.
4. A mastery game places that family under coordinated design pressure.
5. Completion may crystallize the learned capabilities into a named mastery identity, emblem, title, or gem.

A mastery game should introduce as little unrelated machinery as practical. It may add connective systems required to combine prior lessons, but it should not bury the integration examination beneath another full curriculum.

Previously learned systems may recur freely. There are no artificial bans on reuse. Each earlier game retains ownership of the first formal teaching of its primary discipline; the mastery game proves composition, persistence, interoperability, and judgment.

## Not a Minigame Anthology

A mastery game is not ten prototypes stapled together behind a menu.

Required mastery properties include:

- one persistent world;
- one shared progression state;
- one player identity;
- one economy or resource network;
- one inventory or capability state where appropriate;
- outputs from one gameplay mode becoming inputs to another;
- specialized-mode actions visibly changing the shared world;
- intentional, diegetic transitions;
- an in-world reason for every gameplay grammar;
- clear player understanding of why a transition occurred and what it affects.

A specialized mode that produces no meaningful consequence outside itself remains an isolated minigame. It does not satisfy mastery composition.

## The Dimensional-Threshold Principle

A diegetic threshold may change the dimensional language of the game without breaking world continuity.

The important precedent is not merely that a character enters another level. A character may cross a visible in-world boundary and cause the game to change camera, control, dimensional, interaction, or presentation grammar while retaining identity and consequence.

Examples include:

- a 3D world entering a 2D side-scrolling space;
- a side-scrolling world entering top-down exploration;
- continuous adventure entering a fixed workshop interaction;
- traversal entering a card, dice, planning, farming, or management surface;
- modern presentation entering a retro or alternate visual language.

Possible thresholds include a pipe, doorway, cave mouth, tower, hatch, mirror, dream gate, workshop station, tavern table, ancient mechanism, or magical portal.

Continuity comes from preserved player state, world state, resources, progression, and consequences—not from forcing every mode to use the same camera.

## Academy-Wide Tier Rhythm

```text
lesson capability
→ bounded game proof
→ cumulative tier
→ mastery game
→ earned studio identity
```

Possible mastery identities such as `Worldsmith`, `Gamewright`, `Systems Architect`, or `World Forger` remain provisional examples. This doctrine does not select final names.

## Mastery Acceptance Criteria

A tier mastery game should demonstrate:

- shared state across gameplay modes;
- reliable save/load across transitions when persistence belongs to that tier;
- outputs from one system feeding another;
- coherent visual and interaction grammar;
- transitions that preserve player orientation;
- no silent loss of inventory, progression, settings, or world changes;
- at least one meaningful contribution from every required tier lesson;
- cumulative use of the visual, audio, accessibility, input, runtime, and polish systems available when the mastery game is built;
- human-review evidence that the result feels like one world rather than an anthology;
- a mastery-specific lessons-learned record after completion.

### Limited New-System Budget

Connective systems are allowed only where integration genuinely requires them. Examples may include a shared save model, world-state bridge, transition coordinator, unified economy, or cross-mode inventory contract.

Every proposed new system should answer:

1. Which prior lessons does this connect?
2. Why can the mastery proof not work without it?
3. How is its scope bounded?
4. Does it deepen composition, or merely add another feature?

## Relationship to Pass-Specific Curricula

The Tier 1.5 visual-integration curriculum teaches one new headline visual discipline in each of the ten games while allowing all earlier disciplines to recur.

The eventual Tier 1 mastery game should inherit the completed mechanical, visual, audio, accessibility, input, optimization, and polish passes available at the time it is built. It should not freeze itself to the state of the games when this doctrine was written.

The existence of the visual plan does not authorize the mastery game. Implementation belongs to a separately proposed and approved future boundary.

## CodeCraft Structural Precedent

Chapter Zero's Operation Mastery provides the conceptual curriculum rhyme:

```text
isolated capabilities
→ coordinated pressure test
→ higher-order mastery identity
```

This document does not copy, relocate, or reinterpret CodeCraft issue scripts. Tiny Goblin Academy and CodeCraft are not claimed to be technically identical. The precedent is structural: mastery is demonstrated through coordinated use rather than possession of one more isolated technique.

## Future-Tier Extensibility

Composition is the persistent doctrine; genre is not.

Later mastery games may use:

- a systems-heavy simulation;
- a larger quest world;
- a 3D environment;
- a cooperative or multiplayer structure;
- a cross-dimensional experience;
- another backbone appropriate to the capabilities taught by that tier.

The Tier 1 kingdom/settlement structure is one concept seed, not a mandatory template for every future mastery game.

## Governance and Approval Boundary

Before any mastery game begins, a future approved plan must define:

- the exact tier capabilities being examined;
- required versus optional lesson contributions;
- the shared-state contract;
- the limited new-system budget;
- the transition and persistence contract;
- the intended engine and repository boundary;
- evidence and human-review requirements;
- the schedule and stop conditions.

Until then:

- no mastery repository exists;
- no prototype is authorized;
- no asset acquisition is authorized;
- no production title or mastery identity is canonical;
- no current Tier 1.5 work is displaced.
