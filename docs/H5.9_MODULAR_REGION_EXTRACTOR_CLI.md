# H5.9 Modular Region Extractor CLI Architecture

## 1. Purpose
The H5 asset pipeline currently relies on fragmented, ad-hoc scripts (e.g., `normalize-matrix-sheet.py`, single-purpose extraction scripts). As the scale and variety of assets increase, maintaining separate scripts for each edge case (non-uniform grids, baked glows, different sorting needs) creates significant technical debt. We need a unified, modular extractor tool (`extract-regions.py`) that can handle diverse asset sheets through configurable flags, ensuring reusability and maintaining a clean, canonical asset pipeline.

## 2. Three-Phase Architecture
The extractor is designed around three distinct, configurable phases:

### Phase 1: Clean
Erase the background using a configurable strategy.
- **Flood-fill:** Global BFS flood-fill to erase connected grayscale/checkerboard pixels from the edges.
- **Halo Cleanup:** Specialized passes to target and strip semi-transparent pixels or baked glows (e.g., aggressively cropping a torch glow to leave a sharp sprite).

### Phase 2: Detect
Find what remains using pure pixel data.
- **Connected Components:** Uses `scipy.ndimage.label` to find contiguous islands of non-transparent pixels, completely ignoring grid assumptions. This flawlessly extracts organically drawn sprites of varying sizes (tall ladders, small buttons).
- **Min-Area Filtering:** Filters out tiny artifact dust or stray pixels to prevent them from being mapped as standalone regions.

### Phase 3: Map & Generate
Order the detected sprites and write the manifests.
- **Sorting Strategies:** Sorts the detected bounding boxes by coordinates (e.g., top-to-bottom, left-to-right) so IDs map logically.
- **Manifest Output:** Generates the `regions.json` manifest dynamically with the exact, true bounds of each sprite.

## 3. CLI Flags Specification
The proposed CLI (`scripts/asset-pipeline/extract-regions.py`) will accept the following flags:

- `--source` (required): Input PNG path
- `--manifest` (required): Output JSON path
- `--cleanup-mode`: `flood` | `grid-slice` | `color-key`
- `--halo-cleanup`: `none` | `aggressive` | `conservative`
- `--detect`: `connected-components` | `grid-based`
- `--min-area`: Pixel threshold (default: 50)
- `--sort`: `y-x` | `x-y` | `manual`
- `--out`: Evidence output directory

## 4. Usage Examples

**Level 8 Construction Pieces (Aggressive Halo, Connected-Components):**
```bash
python scripts/asset-pipeline/extract-regions.py \
  --source assets/academy/games/one-room-platformer/tga-one-room-platformer-sideview-construction-pieces-concept-v0.1.png \
  --manifest manifests/academy.platformer-construction-pieces.regions.json \
  --cleanup-mode flood \
  --halo-cleanup aggressive \
  --detect connected-components \
  --min-area 100 \
  --sort y-x
```

**Future Sprite Sheets (Different Modes):**
```bash
python scripts/asset-pipeline/extract-regions.py \
  --source assets/future/sheet.png \
  --manifest manifests/future.sheet.regions.json \
  --cleanup-mode grid-slice \
  --detect grid-based \
  --sort x-y
```

## 5. Integration Points
- **Replaces `normalize-matrix-sheet.py`:** Absorbs the global flood-fill functionality into a modular step.
- **Feeds `make-region-evidence.py`:** The generated `regions.json` manifest perfectly feeds into our existing UI evidence generator to produce contact sheets and bounding box overlays.
- **Compatibility:** Fully compatible with the existing H5.x pipeline, acting as the canonical entry point for all region extraction tasks.

## 6. Deferred Status Note
This architecture was intentionally **deferred** for the Level 8 Birthday Build to avoid premature abstraction. Building and debugging a robust flag parser and modular framework would have introduced unnecessary technical debt and delayed the immediate goal of making the game playable. It will be implemented after Level 8 is fully playable and tested.

## 7. Next Actions
- **When to revisit:** After the v0.1 completion of the One-Room Platformer and the Birthday Build.
- **Validation needed:** The single-purpose script used for Level 8 must be proven stable in-engine, and the exact threshold parameters (e.g., halo cleanup tolerances, min-area thresholds) must be validated before they are codified into the universal CLI flags.
