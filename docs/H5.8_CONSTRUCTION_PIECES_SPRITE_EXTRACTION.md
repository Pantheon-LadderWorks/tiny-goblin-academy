# H5.8 Construction Pieces Sprite Extraction

## 1. The Problem Statement
During the initial processing of the platformer construction pieces (`tga-one-room-platformer-sideview-construction-pieces-concept-v0.1.png`), two major issues were encountered:
1. **Non-Uniform Grid Slicing:** The asset sheet does *not* use a perfect 128x128 grid. The actual horizontal grid lines drawn by the artist are non-uniform (e.g., `y = 162, 338, 512, 716, 882`). Using rigid grid math slices right through organic sprites that span multiple rows.
2. **Baked Torch Glow:** The AI generated the torch's orange glow *baked* into the checkerboard background. The checkerboard underneath the glow is composed of alternating shades of orange and brown, breaking standard grayscale flood-fill algorithms and causing ugly checkerboard halos.

## 2. The Sprite-First Detection Approach
Forcing rigid math onto organic art creates fracture points. The canonical H5 pattern is **sprite-first detection**. Instead of defining grid cells, we:
1. Erase the background (checkerboard/grid lines).
2. Discover whatever opaque pixels remain using connected component detection (`scipy.ndimage.label`).
3. Calculate precise bounding boxes from those pixel islands.

This allows tall ladders, small buttons, and uniquely shaped props to be extracted flawlessly without manual grid configuration.

## 3. The Three-Phase Execution Plan
The extraction process operates in three strict phases:

### Phase 1: Clean
Load the raw asset sheet. Run a global BFS flood-fill from the edges to erase the low-saturation checkerboard background and grid lines. Apply an aggressive halo cleanup pass to remove any semi-transparent pixels (alpha < 255) around the edges of sprites, specifically targeting and stripping the baked torch glow to ensure engine-ready, tight-cropped assets. Save the result as `-cleaned-v0.1.png`.

### Phase 2: Detect
Create a binary mask of all non-transparent pixels (alpha > 0) on the cleaned image. Use `scipy.ndimage.label` to find every contiguous island (connected component). Filter out noise by ignoring islands smaller than 100 pixels. Calculate the exact `(x, y, w, h)` bounding box for every valid island.

### Phase 3: Map
Sort the bounding boxes by Y-coordinate (top-to-bottom), then by X-coordinate (left-to-right). Assign logical dot-notation IDs based on their sequential order and position, then write the structured regions out to the `.regions.json` manifest.

## 4. Proposed CLI Abstraction (Future Year 2 Architecture)
While the immediate implementation uses a single-purpose script for speed, the eventual modular CLI (`extract-regions.py`) should accept these parameters:
```bash
python scripts/asset-pipeline/extract-regions.py \
  --source <input_sheet> \
  --manifest <output_manifest> \
  --cleanup-mode flood \
  --halo-cleanup aggressive \
  --detect connected-components \
  --min-area 100 \
  --sort y-x
```
